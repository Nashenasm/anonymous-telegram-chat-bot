# Anonymous Telegram Chat

ربات چت ناشناس دوطرفه برای Telegram با جفت‌سازی تصادفی، ترجیح جنسیتی، صف انتظار، قطع مکالمه، بلاک و پنل مدیریتی ساده. این پروژه در زمان اجرا به Manus یا Atria وابسته نیست و روی Vercel، هر Node.js host، VPS یا کانتینر اجرا می‌شود.

## قابلیت‌های اصلی

کاربر از یک دکمه قابل‌تنظیم با عنوان پیش‌فرض «وصل کن به ناشناس» وارد فرایند می‌شود. جنسیت فقط یک‌بار ثبت می‌شود، سپس کاربر یکی از «دختر»، «پسر» یا «مهم نیست» را برای ترجیح اتصال انتخاب می‌کند. صف انتظار با دکمه «انصراف» مدیریت می‌شود. پس از اتصال، پیام‌ها فقط از طریق ربات منتقل می‌شوند و دو طرف دکمه «قطع مکالمه» دارند. قطع مکالمه در ۱۵ ثانیه اول مجاز نیست و پس از آن تأیید دو مرحله‌ای و گزینه بلاک با دلیل ارائه می‌شود.

در صفحهٔ اصلی دکمهٔ «لینک ناشناس من» یک پیوند ثابت `t.me/<bot>?start=<token>` می‌سازد. توکن پیوند با HMAC از روی توکن ربات تولید می‌شود و فقط digest آن در PostgreSQL ذخیره می‌شود؛ شناسهٔ گیرنده داخل URL افشا نمی‌شود. ورود از این پیوند، ارسال یک پیام اولیه را باز می‌کند. تا وقتی گیرنده پیام اولیه را قبول نکند، متن به او تحویل نمی‌شود؛ ردکردن پیام برای آن فرستنده مجوز ایجاد نمی‌کند. پس از قبول، همان فرستنده در پیام‌های بعدی دوباره درخواست اجازه نمی‌بیند. «پاسخ دادن» برای هر نوبت فقط یک پیام می‌فرستد و «بلاک کردن» پس از تأیید، مجوز و پیام‌های معلق دو طرف را حذف می‌کند. متن‌های این فرایند در حالت ناشناس نگه داشته می‌شوند و به چت تصادفی منتقل نمی‌شوند.

جفت‌سازی تصادفی تنها وقتی دوطرفه سازگار است انجام می‌شود: هم ترجیح فرد درخواست‌کننده و هم ترجیح کاربر منتظر باید جنسیت طرف مقابل را بپذیرند.

پنل خصوصی با دستور `/manpin` فقط برای شناسه‌های داخل `ADMIN_TELEGRAM_IDS` باز می‌شود. در نسخه فعلی مدیر می‌تواند نام سه دکمه عمومی را تغییر دهد و ربات را خاموش یا روشن کند.

## رفع پیام‌های تکراری

وبهوک هر `update_id` تلگرام را در جدول `processed_updates` به‌صورت اتمیک ثبت می‌کند. اگر تلگرام به علت timeout یا خطای شبکه همان update را دوباره ارسال کند، update دوم بدون ارسال دوباره پیام نادیده گرفته می‌شود. برای جلوگیری از تکرار تاریخی، رکوردهای قدیمی را می‌توان دوره‌ای حذف کرد:

```sql
DELETE FROM processed_updates WHERE processed_at < NOW() - INTERVAL '14 days';
```

## اجرای مستقل

Node.js 20 یا جدیدتر و PostgreSQL لازم است. نصب و آماده‌سازی:

```bash
cp .env.example .env
npm install
psql "$DATABASE_URL" -f db/schema.sql
npm run build
npm test
npm start
```

در نصب تازه، `db/schema.sql` تمام جدول‌های چت تصادفی و پیام ناشناس را می‌سازد. اگر پایگاه‌دادهٔ موجود را ارتقا می‌دهید، ابتدا از آن backup بگیرید و `db/schema-v3.sql` را روی همان پایگاه‌داده اجرا کنید؛ این مهاجرت ستون انقضای پیوند را nullable می‌کند و جدول‌های اجازه، پیام‌های معلق و بلاک ناشناس را می‌سازد. سپس کد جدید را مستقر کنید.

سرور مستقل روی `0.0.0.0:$PORT` گوش می‌دهد و مسیرهای `/health` و `/api/webhook` را ارائه می‌کند. برای Vercel، فایل `api/webhook.js` به‌عنوان Function استفاده می‌شود و `vercel.json` محدودیت اجرا را تنظیم می‌کند.

متغیرهای ضروری عبارت‌اند از `TELEGRAM_BOT_TOKEN`، `TELEGRAM_WEBHOOK_SECRET`، `DATABASE_URL` و `ADMIN_TELEGRAM_IDS`. توکن‌ها را commit نکنید. `DATABASE_SSL=false` فقط برای PostgreSQL محلی استفاده شود.

## تنظیم وبهوک

بعد از استقرار، URL عمومی خود را جایگزین کنید:

```bash
curl -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -d "url=https://YOUR_HOST.example/api/webhook" \
  -d "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
  -d "drop_pending_updates=true"
```

`drop_pending_updates=true` برای راه‌اندازی پاک و جلوگیری از پردازش پیام‌های قدیمی اختیاری است.

## پایداری و امنیت

تمام وضعیت صف، اتصال، جنسیت، بلاک‌ها و تنظیمات در PostgreSQL نگهداری می‌شود؛ بنابراین حذف حساب Manus یا خاموش شدن این محیط، مالکیت یا داده‌های ربات را از بین نمی‌برد. برای اجرای ۲۴ساعته، از یک سرویس Node.js دائمی یا Function وبهوک روی ارائه‌دهنده‌ای که خودتان کنترل می‌کنید استفاده کنید. برای production، دسترسی PostgreSQL و توکن Telegram را در secret manager نگه دارید و یک backup دوره‌ای از دیتابیس داشته باشید.

# Anonymous Telegram Chat

ربات چت ناشناس دوطرفه برای Telegram با جفت‌سازی تصادفی، ترجیح جنسیتی، صف انتظار، قطع مکالمه، بلاک، پروفایل، مانو کوین و پنل مدیریتی ساده. این پروژه در زمان اجرا به Manus یا Atria وابسته نیست و روی Vercel، هر Node.js host، VPS یا کانتینر اجرا می‌شود.

## قابلیت‌های اصلی

- چت ناشناس تصادفی با دکمه‌های معمولی داخل ربات، ترجیح جنسیتی دوطرفه، صف انتظار، قطع مکالمه، بلاک و گزارش.
- لینک ناشناس ثابت برای هر کاربر با رضایت‌گیری قبل از نمایش پیام و دکمه‌های inline فقط در همان جریان پیام ناشناس.
- پروفایل با مانو کوین، تاریخ عضویت با ساعت ۲۴ساعته، آیدی عددی، جنسیت و باقی‌ماندهٔ مانو پلاس.
- کاربر جدید در اولین ورود ۲۰ مانو کوین می‌گیرد؛ ورود از لینک اختصاصی ۵ مانو کوین برای صاحب لینک و ورود از لینک ناشناس ۳ مانو کوین برای صاحب لینک ثبت می‌کند.
- اکانت پلاس با قیمت‌های ثابت: ۱ ماهه ۱۰۰، ۳ ماهه ۲۵۰، ۶ ماهه ۴۵۰ و ۱۲ ماهه ۸۰۰ مانو کوین. تأیید خرید با دکمه‌های inline انجام می‌شود.
- کاربر پلاس یک نشان قابل تغییر دارد؛ مدیران همیشه پلاس نامحدود هستند و نشان پیش‌فرض مدیر سه ✨ است. کاربران معمولی نشان ندارند.

## اجرای مستقل

Node.js 20 یا جدیدتر و PostgreSQL لازم است:

```bash
cp .env.example .env
npm ci
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/schema.sql
npm run build
npm test
npm start
```

برای پایگاه‌دادهٔ موجود، ابتدا backup بگیرید و سپس `db/schema-v4.sql` را اجرا کنید. این migration ستون‌های پلاس، نشان، نقش، کد دعوت و جدول خرید پلاس را اضافه می‌کند. روی دیتابیس حاوی داده، `schema.sql` را دوباره به‌عنوان نصب تازه اجرا نکنید.

متغیرهای ضروری عبارت‌اند از `TELEGRAM_BOT_TOKEN`، `TELEGRAM_WEBHOOK_SECRET`، `DATABASE_URL` و `ADMIN_TELEGRAM_IDS`. `BOT_USERNAME` اختیاری است؛ اگر تنظیم نشود، نام کاربری ربات از Telegram `getMe` خوانده می‌شود. توکن‌ها را commit نکنید.

## تست و build

```bash
npm run build
npm test
```

تست‌های فعلی شامل قرارداد دکمه‌ها، مسیر لینک ناشناس، idempotency، سازگاری ترجیحات، schema پلاس/دعوت و محدودیت ۱۵ ثانیه‌ای قطع مکالمه است.

## Vercel و webhook

برای Vercel، فایل `api/webhook.js` به‌عنوان Function استفاده می‌شود. پس از استقرار، متغیرهای محیطی را در پروژهٔ Vercel قرار دهید و webhook را ثبت کنید:

```bash
curl -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -d "url=https://YOUR_HOST.example/api/webhook" \
  -d "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
  -d "drop_pending_updates=true"
```

مسیر سلامت اجرای مستقل `GET /health` و مسیر webhook `POST /api/webhook` است.

## استقلال و انتقال

سورس، migrationها، تست‌ها و راهنمای انتقال در همین مخزن هستند. اجرای production هیچ درخواست runtime به Manus یا Atria نمی‌فرستد؛ Atria فقط می‌تواند در مرحلهٔ توسعه و review استفاده شود. برای انتقال، repository را روی میزبان جدید deploy کنید، متغیرهای محیطی را در secret manager مقصد قرار دهید، PostgreSQL را با dump/restore منتقل کنید و webhook Telegram را به URL جدید تغییر دهید. جزئیات در [راهنمای استقلال و بازیابی](docs/independence-and-recovery.md) آمده است.

## جویین اجباری

مدیران از `/manpin` → «تبلیغات» → «جویین اجباری» منابع کانال، گروه، ربات، وب‌اپ و وب‌سایت را مدیریت می‌کنند. هنگام ثبت هر منبع، در مرحلهٔ نهایی با چهار دکمهٔ شیشه‌ای می‌توان مخاطبان را روشن/خاموش کرد: کاربر معمولی دختر/پسر و کاربر پلاس دختر/پسر. انتخاب‌ها در پروفایل `gender` و زمان اعتبار پلاس (`plus_expires_at`) اعمال می‌شوند؛ اگر جنسیت پروفایل خالی باشد، منبع برای گروه عادی/پلاس او در صورتی اعمال می‌شود که دست‌کم یکی از دو جنسیت آن گروه انتخاب شده باشد. منبع فقط پس از تأیید نهایی ساخته می‌شود و انتخاب مخاطب در گزارش/جزئیات نمایش داده می‌شود. migration افزایشی نسخهٔ ۷ در `db/schema-v7-mandatory-audience.sql` است؛ راه‌اندازی runtime نیز ستون‌ها و تنظیمات را idempotent آماده می‌کند.

برای کانال و گروه، ربات لینک دعوت خصوصی می‌سازد و فقط در پیام خصوصی مدیر آیدی عددی و لینک دعوت را می‌آورد. کاربر متن قابل‌تنظیم و دکمه‌های شیشه‌ای لینک‌دار را می‌بیند؛ دکمه‌ها برای حفظ شمارش همچنان شیشه‌ای و لینک‌دار هستند. از «کنترل ظاهری» می‌توان متن پیام، نام دکمهٔ عضویت، نام دکمهٔ بررسی، چیدمان دکمه‌ها و نمایش شمارهٔ منبع را تنظیم کرد. رنگ واقعی دکمه‌ها در اختیار تلگرام است. عضویت فقط پس از فشردن «بررسی عضویت» و تأیید Telegram شمرده می‌شود و هر کاربر برای هر ثبت منبع یک‌بار محاسبه می‌شود.

در منوی «وضعیت»، فقط منابع در حال اجرا، صف یا زمان‌بندی‌شده نمایش داده می‌شوند؛ سفارش تکمیل‌شده از فهرست عملیاتی خارج می‌شود ولی تاریخچه/پست گزارش آن می‌ماند. برای جزئیات از فرمان پیگیری مانند `/mj_ab12cd34` استفاده کن. صفحهٔ وضعیت فقط یک فهرست می‌فرستد؛ فهرست زمان‌بندی کنترل‌های قبلی را نگه می‌دارد. پایان ثبت منبع نیز فقط تأیید متنی و منوی معمولی مدیر را می‌دهد، نه کنترل‌های شیشه‌ای.

دکمه‌های «حذف»، «امور پیگیری» و «خاموش/روشن» از منوی جویین اجباری برداشته شده‌اند؛ خاموش/روشن‌کردن کلی ربات در پنل اصلی محفوظ است.

### زمان‌بندی بیرونی هر دقیقه

برای فعال‌شدن دقیق اعلان‌های زمان شروع، یک سرویس زمان‌بندی بیرونی را روی یک دقیقه تنظیم کنید:

- درخواست: `GET https://YOUR_HOST/api/mandatory-jobs`
- سرآیند: `Authorization: Bearer <CRON_SECRET>`
- در متغیرهای محیطی Vercel/هاست، `CRON_SECRET` را روی مقدار تصادفی محرمانه با حداقل ۳۲ بایت بگذارید؛ برای نمونه آن را با `openssl rand -hex 32` بسازید. همان مقدار را فقط در تنظیمات امن سرویس زمان‌بندی هم ثبت کنید.
- زمان‌بندی: هر دقیقه. درخواست بدون سرآیند معتبر رد می‌شود. مسیر، زمان‌بندی‌ها، تکمیل سفارش‌ها، اعلان‌ها و همگام‌سازی تدریجی گزارش‌ها را پردازش می‌کند.

گزینهٔ رایگان [cron-job.org](https://cron-job.org/en/) اجرای هر دقیقه و سرآیند سفارشی را پشتیبانی می‌کند؛ طبق [FAQ رسمی](https://cron-job.org/en/faq/)، هر اجرا حداکثر ۳۰ ثانیه منتظر می‌ماند و زمان‌بندی دقیق/بدون تأخیر تضمین نمی‌شود. یک job دقیقه‌ای حدود ۴۳٬۲۰۰ درخواست کوچک در ماه می‌فرستد؛ در هر اجرا فقط زمان‌بندی‌های موعدرسیده و حداکثر یک پست گزارش و یک اعلان پردازش می‌شود، بنابراین بار معمول کم است. مصرف invocation تابع در Vercel و درخواست‌های پایگاه داده تابع طرح/استفادهٔ فعلی شماست؛ پیش از انتقال به طرح دیگر، سهمیهٔ همان حساب را بررسی کنید.

این worker مستقل از Manus و Atria است؛ برای انتقال، همان endpoint و متغیر محرمانه را در هاست جدید تنظیم کنید و URL سرویس زمان‌بندی را به هاست جدید تغییر دهید.


## کنترل جامع ظاهر و قالب‌ها

از پنل مدیر، مسیر «کنترل ربات» شامل «بخش ظاهری پابلیک» و «بخش ظاهری پرایویسی» است. هر بخش تنظیمات خود را در `bot_settings` به‌صورت JSON نگه می‌دارد و از منطق فنی، نام مانو کوین، قیمت‌های Plus و ساختار اتصال کاربران مستقل است.

- تغییر عنوان و متن هر منو
- تغییر نام دکمه‌های اصلی و متن پاسخ دکمه‌ها و زیرمرحله‌ها
- فعال/خاموش‌کردن ظاهر سفارشی و بازگردانی به پیش‌فرض
- چیدمان پیش‌فرض، تک‌ستونه یا دوستونه
- چهار قالب آماده: «پیش‌فرض فعلی»، «لوکس»، «هالووینی» و «فرندلی»؛ هر قالب برای پابلیک و پرایویسی جداگانه اعمال می‌شود
- همهٔ منوهای این بخش با reply keyboard معمولی تلگرام کار می‌کنند؛ دکمه‌های شیشه‌ای موجود جویین اجباری دست‌نخورده می‌مانند چون برای لینک و شمارش عضویت لازم‌اند

برای دیتابیس‌های موجود، قبل از deploy از دیتابیس backup بگیرید و سپس migration زیر را اجرا کنید:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/schema-v8-appearance-and-owner-tools.sql
```

## ابزارهای فنی مالک

در مسیر «گزارش‌ها» گزینهٔ «بخش فنی» فقط برای `OWNER_TELEGRAM_ID` فعال است؛ حتی ادمین‌های معمولی اجازهٔ اجرای آن را ندارند. این بخش سه دکمه دارد:

- «فایل اوپن سورس»: بستهٔ ZIP از سورس جاری، بدون `.env`، `.git` و `node_modules`
- «بک آپ دیتابیس»: خروجی فشردهٔ SQL از وضعیت فعلی جداول عمومی
- «وضعیت سرور»: وضعیت runtime، حافظه، uptime، اتصال دیتابیس، Telegram و آمار کاربران

این قابلیت‌ها به Manus یا Atria وابسته نیستند و روی اجرای مستقل Node.js/Vercel قابل انتقال هستند. برای بک‌آپ دیتابیس، migrationها را نیز کنار فایل SQL نگه دارید.


## بک‌آپ چندفرمتی

دکمهٔ «بک آپ دیتابیس ZIP» یک آرشیو چندفرمتی ارسال می‌کند. داخل آن `database.sql` برای Restore مستقیم PostgreSQL، `database.json` برای انتقال ساختاری، `tables/*.json` برای هر جدول، `tables/*.csv` برای Excel/import، `schema.json` برای metadata ستون‌ها، `manifest.json` و `README.txt` قرار دارد. بنابراین ZIP فقط یک gzip با پسوند عوض‌شده نیست و برای Restore، مهاجرت، بررسی دستی و پردازش داده قابل استفاده است.

فایل اوپن‌سورس نیز ZIP مستقل با `SOURCE_MANIFEST.json` است و `.env`، `.git` و `node_modules` را وارد نمی‌کند.

## سیستم طراحی چندلایه

قالب‌ها اکنون علاوه بر صفحهٔ اصلی، stateهای انتخاب ترجیح، انتخاب جنسیت، انتظار، مکالمه، تأیید قطع، بعد از قطع، دلیل بلاک، پروفایل، کوین، Plus، لینک ناشناس و صفحه‌های مدیریت را پوشش می‌دهند. هر لایه عنوان، متن، دکمه و پاسخ داخلی قابل ویرایش دارد و فهرست ویرایش به‌صورت صفحه‌بندی‌شده همهٔ آیتم‌ها را نمایش می‌دهد. «فونت سفارشی واقعی» در پیام تلگرام ممکن نیست؛ به‌جای آن از تایپوگرافی یونیکد، قاب‌ها، فاصله‌گذاری، نشانه‌گذاری و جمله‌پردازی اختصاصی استفاده شده تا ظاهر در خود Telegram قابل انتقال و مستقل بماند.


## انتخاب فرمت هنگام دریافت بک‌آپ

در بخش فنی، با انتخاب «فایل اوپن سورس» ابتدا فرمت `ZIP` یا `TAR.GZ` پرسیده می‌شود. با انتخاب «بک آپ دیتابیس» نیز می‌توان `ZIP چندفرمتی`، `SQL`، `JSON` یا `CSV (ZIP)` را انتخاب کرد. بنابراین نام فایل یا قالب ظاهری دکمه‌ها هیچ‌وقت منطق داخلی را تغییر نمی‌دهد و منطق بر اساس شناسهٔ ثابت هر عملیات اجرا می‌شود.

## طراحی عمیق قالب‌ها

قالب‌های لوکس، هالووینی و فرندلی فقط پوستهٔ رنگی نیستند. هر قالب برای منوی اصلی، انتظار، انتخاب ترجیح، انتخاب جنسیت، مکالمه، پایان مکالمه، بلاک، پروفایل، ایموجی، مانو کوین، Plus، لینک ناشناس و بخش‌های مدیریتی متن و دکمهٔ اختصاصی دارد. قالب‌ها همچنین لحن پیام‌های بازخورد، معماری چینش دکمه‌ها و مسیرهای بخش خصوصی را تغییر می‌دهند.

شناسهٔ فنی دکمه‌ها مثل `connect`، `profile`، `block` و `technical` ثابت می‌ماند. به همین دلیل، طراحی می‌تواند کاملاً عوض شود بدون اینکه روند اصلی ربات، بک‌آپ، دیتابیس یا منطق مدیریتی به نام نمایشی دکمه وابسته شود.
